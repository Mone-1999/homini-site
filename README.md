# Homini

Адаптивный сайт деревянных построек для загородной жизни. Реализован по согласованному объединённому макету: белый фон, Inter, слайдер на первом экране, натуральные материалы, каталог и подбор решения.

## Локальный запуск

Нужен Node.js 22.12+ или 24 LTS. В облачной среде проверено на Node.js 24.

```sh
npm ci
npm run dev
```

Команды выполняются из корня `homini-site`. Используйте имеющуюся рабочую копию; отдельный Git worktree не нужен.

## Сборка и проверки

```sh
npm run build
npm run preview
npm test
```

`build` создаёт статический сайт в `dist/` для размещения на статическом хостинге. `preview` предназначен для локальной проверки собранного сайта.

Playwright проверяет production-сборку: сам запускает preview на порту 4173. Перед `npm test` выполните `npm run build`. В облачной среде используется `/usr/bin/chromium`; на другом компьютере передайте `CHROMIUM_PATH` с путём к установленному Chromium/Chrome. Тесты проверяют изображения и логотипы, загрузку Inter, слайдер и жесты, фильтры, диалоги и клавиатуру, форму, подготовку письма, скачивание заявки, мобильное меню, уменьшение анимации и ширины 320–1440 px.

При ограничениях на запись в домашний каталог установите зависимости командой `npm --cache /tmp/homini-npm-cache ci`.

## Что работает

- Слайдер из трёх визуализаций: ручное переключение стрелками, индикаторами, клавиатурой и горизонтальным жестом. Автопрокрутки нет.
- Оригинальный логотип в шапке и белая версия в подвале.
- Минималистичные линейные SVG-иконки без внешних библиотек.
- Каталог из восьми категорий с фильтрами «Для отдыха» и «Для порядка».
- Подробности каждой категории в доступном диалоге.
- Подбор решения за три шага с сохранением ответов при возврате назад.
- Проверка контакта: телефон, email или Telegram.
- Подготовка письма на `sokolov.design@gmail.com`, копирование и скачивание текста заявки.
- FAQ, мобильная навигация, управление с клавиатуры и уменьшение анимации по настройкам устройства.

## Заявки

Адрес Homini задаётся в **`src/config.js`**. Форма создаёт `mailto:`-ссылку с темой и текстом. Посетитель открывает её в своём почтовом приложении и самостоятельно отправляет письмо. Сайт не отправляет письма в фоне и не сообщает о доставке. Если почтовое приложение не настроено, доступны копирование и скачивание заявки, а адрес показан в подвале.

Сервера, внешней аналитики, cookies и сохранения заявок в localStorage нет. Персональные данные остаются в памяти страницы; при передаче используются почтовые сервисы самого посетителя. Автоматическая отправка без почтового клиента потребует отдельного серверного обработчика и настройки оператора персональных данных. Секреты нельзя добавлять в клиентский код.

## Содержимое и изображения

- `src/main.js` — диалоги, подбор решения, мобильное меню и обработка форм.
- `src/layout.js` — структура страницы.
- `src/data.js` — категории и FAQ.
- `src/carousel.js` — доступный слайдер с ручным управлением.
- `src/icons.js` — небольшой согласованный набор линейных иконок.
- `src/style.css` — адаптивные стили.
- `public/images/` — локальные WebP-изображения без зависимости от внешнего фотосервиса.
- Inter Variable с оптическими размерами включается в сборку локально через Fontsource. Сервисы внешних шрифтов не требуются.
- Логотипы: `public/images/logo.svg` и `public/images/logo-white.svg`. Это предоставленные SVG без изменения цветов и пропорций.
- Все изображения обновлены на согласованную серию визуализаций по референсам построек и чёрных коннекторов. Каталог включает детский домик и качели; баннер объединяет летнюю кухню, беседку и хозблок. Обзор серии находится в `docs/new-images/`, согласованный дизайн — в `docs/design-options/06-hybrid/`.

Изображения обозначены как визуализации. Подтверждённых цен, характеристик конкретных моделей, сроков, гарантий и реальных кейсов в исходных материалах нет: сайт их не выдумывает. Каталог пока описывает категории, а не серийные модели с паспортами изделий. Реальные фотографии, модели, размеры, комплектацию и условия можно добавить после подтверждения. Регион работы не ограничен в текстах; посетитель указывает местоположение участка для обсуждения.

## Просмотр через GitHub Pages

Репозиторий: https://github.com/Mone-1999/homini-site

1. Откройте **Settings → Pages** в репозитории.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. На вкладке **Actions** откройте **Publish Homini to GitHub Pages**. Если публикация ещё не выполнилась, нажмите **Run workflow → main → Run workflow**.
4. После успешного завершения задания `deploy` сайт будет доступен по адресу **https://mone-1999.github.io/homini-site/**.

При следующих изменениях в `main` сайт будет обновляться автоматически. Если в Settings нет возможности включить Pages, проверьте права владельца и доступность GitHub Pages для тарифа и видимости репозитория. Workflow не меняет видимость репозитория.

Все пути к шрифтам, стилям и изображениям учитывают размещение в подпапке `/homini-site/`. Секреты и отдельный платный сервер для этой статической версии не требуются.
